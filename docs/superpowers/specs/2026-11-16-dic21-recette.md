# DIC-21 : recette sur téléphone

## Périmètre

La recette utilise deux enregistrements synthétiques datés de 2099 et un dossier Drive dédié. Aucun envoi global, transcription, synthèse ni suppression de réunion n'a été demandé. La version signée 0.6.0 a été installée sur la 0.5.0 après comparaison des certificats de signature, sans désinstallation.

## Résultats vérifiés

| Scénario | Résultat observé |
| --- | --- |
| Tests Android isolés | Les 31 tests passent sur le téléphone déverrouillé. |
| Transport PATCH Android | Le serveur HTTP loopback reçoit PATCH et le corps synthétique attendu. |
| Fiche, choix VTT + MD | Les deux documents du premier enregistrement sont déposés ; son MP3 est absent de Drive. |
| Liste en sélection, choix MP3 + VTT + MD | Les trois fichiers du second enregistrement sont déposés. |
| Nombre de fichiers distants | Le catalogue Drive contient exactement cinq fichiers, sans doublon de nom. |
| Détection à taille identique | Avec VTT + MD déjà actif et l'étape faite, remplacer B par C dans les deux documents sans changer leur taille remet Drive à faire. |
| Renvoi des documents modifiés | L'étape redevient faite après envoi ; la lecture indépendante de Drive retrouve la version C dans le VTT et le MD. |
| Remplacement, pas duplication | Les identifiants Drive du VTT et du MD sont identiques avant et après ce dernier envoi ; le catalogue reste à cinq fichiers. |
| Annulation | Après annulation du dialogue, la fiche reste à faire. L'absence de requête réseau n'a pas été instrumentée dans ce geste manuel. |
| Choix conservé après retour à l'app | VTT + MD reste sélectionné après Home puis réouverture ; l'arrêt du processus n'a pas été démontré. |

## Corrections des tests

La première suite complète révélait deux défauts de tests préexistants : un test JUnit renvoyait un Boolean et une fixture de transcription utilisait une adresse invalide. La signature Unit et l'adresse synthétique valide ont été corrigées sans changement du comportement applicatif.

Le test PATCH dispose désormais d'une configuration réseau versionnée limitée à la variante debug : le HTTP en clair est autorisé uniquement pour le loopback, et refusé par défaut ailleurs. La variante release ne reçoit pas cette configuration.

## Échecs intermédiaires et limites

Un essai complet a été interrompu dans ProcessingNotifications sans cause établie. Le test seul puis la suite complète ont ensuite réussi. Un autre rejeu avec écran verrouillé a fait échouer les tests Compose ; le dernier rejeu après déverrouillage réussit avec 31 tests en 24,472 secondes.

Le remplacement d'un fichier réellement exporté par DOWAY, l'échec réseau suivi d'une reprise et la persistance après arrêt effectif du processus n'ont pas été recettés sur appareil. Les tests JVM couvrent les chemins d'erreur et de persistance mais ne remplacent pas ces essais.

Les libellés des dossiers téléphone et Drive habituels ont été rétablis. L'URI SAF initiale n'ayant pas été relevée avant le changement temporaire, son identité exacte n'est pas certifiée. Le dernier choix reste VTT + MD. Les fichiers synthétiques et les applications de recette sont conservés : leur suppression nécessite un accord séparé.

Aucun push, fusion ou publication de release n'a été effectué. Cette recette ne clôt pas les scénarios non vérifiés ci-dessus.
