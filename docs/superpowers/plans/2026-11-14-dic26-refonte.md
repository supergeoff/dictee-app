# DIC-26 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Montrer le parcours Téléphone → VTT → MD → Drive et proposer la prochaine action sans ambiguïté.

**Architecture:** Un calcul Kotlin sans Android fournit les étapes, la raison, le badge et l'action à la fiche et à la liste. Compose ne décide pas des priorités. Le coordinateur existant reçoit un appel court de sujet et le dépôt durable conserve les sujets.

**Tech Stack:** Kotlin, Jetpack Compose, coroutines, JUnit, Gradle, clients HTTP existants.

**Spec:** `docs/superpowers/specs/2026-11-14-dic26-refonte-design.md`.

## Global Constraints

- La maquette `docs/superpowers/specs/2026-11-14-dic26-maquette.html` fait foi pour la disposition, les libellés et les couleurs ; la spec fait foi pour le comportement.
- Version initialement prévue 0.4.0 ; la base effective étant déjà en 0.4.1, cette version a été conservée. Ne pas ajouter de dépendance sans nécessité démontrée.
- Produire seulement les fichiers manquants, sauf demande explicite de remplacement ; conserver l'ancien MD jusqu'à promotion.
- L'envoi Drive reste explicite. Aucun enchaînement de récupération, choix Drive ou suppression ne fait partie de DIC-26.
- Conserver la file par nom croissant, une tâche à la fois, et les trois tentatives de synthèse.
- Fixtures synthétiques uniquement ; ni clé, ni transcription réelle, ni chemin personnel dans les commits.
- Chaque lot termine par `./gradlew testDebugUnitTest assembleDebug lint`. Compiler aussi les tests instrumentés avec `./gradlew assembleDebugAndroidTest` avant livraison.
- Aucun push, fusion, déploiement ou release sans accord explicite.

## Review Focus

1. Un ancien fichier reste lisible pendant son remplacement, mais son étape affiche bien le travail en cours (lot 1 et lot 2).
2. Une tâche suspendue ou terminale ne fausse ni le rang ni la tête de file (lot 1).
3. Une provenance MD inconnue ne doit pas être présentée comme un ancien VTT prouvé (lots 1 et 2).
4. Un champ de clé laissé intact ne remplace jamais le secret enregistré par les points affichés (lot 4).
5. Une annulation ou une reprise du processus pendant la demande du sujet ne relance pas indéfiniment cet appel et ne bloque pas le MD (lot 5).
